# 《Marvel's Wolverine》中文攻略站设计规格

日期：2026-08-27  
状态：已完成对话设计确认，等待书面规格复核

## 1. 项目目标

构建一个面向简体中文玩家的《Marvel's Wolverine》发售伴侣型攻略站。网站在游戏发售前提供可靠的官方情报、购买决策信息、玩法机制解析与首发准备指南；游戏发售后可沿用同一内容架构扩展流程、Boss、收集品与配装攻略。

成功标准：

- 覆盖发售日期、平台、开发商、剧情背景、金刚狼能力、战斗系统和核心玩法等已确认信息。
- 以近期搜索意图规划多页面内容集群，形成清晰的内部链接结构。
- 呈现暗黑暴力美学与漫威漫画感，同时形成独立站点品牌，不仿制官方页面。
- 桌面端与移动端均能完整阅读和导航，满足基础无障碍要求。
- 正式构建无错误，代码推送至独立 GitHub 仓库，并通过 Vercel 生产部署。

## 2. 受众与内容定位

主要受众：

- 想确认发售时间、平台、版本和价格的潜在购买者。
- 想在首发前了解战斗、能力、剧情与角色的 PS5 玩家。
- 发售后搜索新手攻略、战斗技巧、技能与收集内容的玩家。

内容定位采用“权威情报 + 首发攻略框架”，不伪装成已经体验完整版的完整攻略站。每条关键内容按来源性质标注：

- **官方确认**：PlayStation、Insomniac Games 或 Marvel Games 公开信息。
- **媒体试玩**：具名媒体基于获准试玩所披露的信息。
- **发售后验证**：尚待正式版实测的攻略结论。

不使用 2023 年数据泄露中的剧情、素材或开发文件；不编造关卡、Boss、技能数值、流程时长或最优配装。

## 3. 已核实的信息基础

网站首发内容以 2026-08-27 可公开核实的信息为准：

- 游戏将于 2026-09-15 登陆 PlayStation 5；为 PS5 平台打造，不登陆 PS4。
- 类型为叙事驱动的单人动作冒险，不是开放世界。
- 开发方为 Insomniac Games，合作方包括 Marvel Games 与 Sony Interactive Entertainment。
- 原创剧情围绕罗根重返离开三年的 X 小队展开。玻利瓦尔·特拉斯克与掠夺者绑架变种人；旅程涉及加拿大、日本东京与马德里坡。
- 已公开角色或势力包括罗根、琴·格蕾、剑齿虎、死亡女、欧米伽红、玻利瓦尔·特拉斯克、掠夺者、X 小队与手合会。

- Last Stand 可在濒危状态触发治疗因子。玩家还会经历摩托追逐与跨载具战斗等大型演出。
- PlayStation 官方页面说明支持 DualSense 触觉与自适应扳机、3D 音效、PS5 Pro 增强以及广泛的视觉、听觉、操作和难度辅助选项。

- 官方故事预告确认前传漫画、手合会与死亡女等信息；完整原声带计划于 2026-08-28 发布。
- 近期获准媒体试玩披露了技能升级、冷却型主动能力、探索区域、挑战活动、任务重玩、新游戏+和 Nightmare Doors 等内容。凡引用这些信息，页面必须标记为“媒体试玩”，不能表述为本站实测。

## 5. 页面与内容结构

### 5.1 首页 `/`

- 固定但可收缩的全站导航。
- 首屏标题“WOLVERINE”和中文主张“猎杀之前，先读懂野兽”。
- 发售倒计时与 PS5、单人、非开放世界等关键事实。
- “开始首发准备”和“拆解战斗系统”两个主要入口。
- 官方确认的游戏概览与来源状态标签。
- 五个核心板块入口：游戏资料、新手入门、战斗系统、角色能力、剧情档案。
- 最新动态卡片和常见问题摘要。

### 5.2 游戏资料 `/game-info`

- 发售时间、平台、开发商、发行合作方、类型与游玩人数。
- 标准版、数字豪华版和预购奖励对比。
- PS5/PS5 Pro、DualSense、3D 音效、辅助功能与中文支持。
- “是否登陆 PC”“是否开放世界”“游戏时长是否确认”等购买前 FAQ。

### 5.3 新手攻略 `/guides/beginner`

- 首发前应知道的系统与设置。
- 新手战斗循环：观察、接近、招架或闪避、连击、积累怒气、治疗与终结。
- 探索、收集和升级信息中哪些已经确认，哪些需要发售后验证。
- 避免把媒体试玩经验写成全流程最优策略。

### 5.4 战斗系统 `/guides/combat`

- 基础攻击、防御、移动、潜行与空中伏击。
- Techniques、Critical Strikes、怒气三阶段、治疗因子与 Last Stand。
- 摩托追逐与跨载具战斗等演出玩法。
- “已确认机制”和“首发后待验证数值”分区。

### 5.5 角色能力 `/characters/wolverine`

- 罗根的利爪、艾德曼合金骨骼、恢复能力、强化感官、体能与战斗经验。
- 分清漫画常规设定与本作已展示的可玩机制。
- 介绍游戏如何通过怒气、受伤反馈、治疗与服装恢复体现角色幻想。

### 5.6 剧情档案 `/story`

- 无重大剧透的剧情前提。
- X 小队、变种人生存危机、特拉斯克与掠夺者。
- 已公开角色关系与主要地点。
- 明确标注原创故事，不把漫画连续性直接套用为游戏事实。

### 5.7 最新动态 `/news`

- 玩法预告与发售日确认。
- SDCC 故事预告、前传漫画与原声带。
- 预购、版本与硬件相关更新。
- 卡片链接到原始来源；首发版本不引入 CMS 或运行时新闻抓取。

### 5.8 错误页面

- 自定义 404 保留站点视觉语言，并提供返回首页和核心攻略入口。

发售后可新增 `/walkthrough`、`/bosses`、`/collectibles` 和 `/builds`，但这些空栏目不会在首发站点中提前发布。

## 6. 视觉系统

视觉方向为“黑色档案馆 + 漫画分镜”，将粗粝、危险和信息可读性结合。

### 6.1 配色

- 页面背景：`#090A0C`
- 面板背景：`#15171B`
- 主强调黄：`#F5C518`
- 辅助深蓝：`#163B65`
- 危险红：`#D9362B`
- 暖白正文：`#F2EFE7`
- 次级文字：使用满足对比度要求的中性灰

### 6.2 构图与品牌语言

- 大号压缩型英文展示字体配合清晰的中文无衬线字体。
- 斜切面板、爪痕分隔线、漫画网点、细颗粒和编号标签。
- 首屏采用不对称构图；内容页使用稳定阅读列，避免视觉效果干扰正文。
- 不使用 Marvel 或 PlayStation 官方 Logo 作为本站标识，也不复制官方页面版式。
- 优先使用 PlayStation 官方页面明确提供下载的媒体图像并标注来源。授权范围不清晰时，改用原创抽象爪痕、烟雾、光束和漫画纹理。
- 不在成品中使用模型手写 SVG 插画；装饰优先采用 CSS 图形和合法图片资产。

### 6.3 响应式与动效

- 桌面端使用宽幅首屏、非对称卡片和纵向章节编号。
- 平板和移动端改为单列卡片、可横向滚动的短标签以及抽屉导航。
- 导航滚动后收缩；发售倒计时在客户端每秒更新。
- 悬停反馈只使用轻微位移、边框高亮和阴影。
- 遵守 `prefers-reduced-motion`，关闭非必要转场。

## 7. 技术架构

- Next.js App Router、TypeScript 和 React。
- 内容以本地 TypeScript 数据或轻量内容模块维护，不使用数据库、CMS、账户或评论系统。
- 页面尽可能静态生成；仅导航菜单和倒计时等小型交互使用客户端组件。
- 共享层包含全站导航、页脚、来源标签、内容卡片、章节标题、面包屑和 FAQ 组件。
- 数据层与展示层分离：事实、来源、更新时间、新闻和 FAQ 从集中内容模块导入。
- 不在浏览器中请求第三方 API，避免因外部服务失败导致页面不可用。
- 使用项目自带的包管理器与锁文件；不得把密钥提交到 Git。

## 8. SEO 规范

- 每个路由拥有独立的 title、description、canonical、Open Graph 与 X 元数据。
- 根布局设置可信的生产域名作为 metadata base；部署域名确认前不伪造 canonical。
- 首页输出 `WebSite` 与 `VideoGame` JSON-LD。
- 内容页输出适用的 `Article` 和 `BreadcrumbList` JSON-LD。
- FAQ 必须先作为可见正文存在，再决定是否输出 `FAQPage` 结构化数据。
- 自动提供 `sitemap.xml` 和 `robots.txt`。
- 语义化标题层级、图片替代文本、面包屑与相关内容内链完整。
- 分享图为原创黄黑红漫画风横版图，文字需清晰且与站点标题一致。
- 页面底部列出来源与最后更新时间，避免把媒体试玩当作官方信息。

## 9. 无障碍与错误处理

- 所有交互可通过键盘完成，焦点样式明显。
- 导航抽屉具有正确的可访问名称、展开状态与关闭方式。
- 文字与背景保持足够对比度；不能只靠颜色表达来源状态。
- 图片提供描述性替代文本，纯装饰图像使用空替代文本。
- 倒计时在 JavaScript 不可用时仍显示静态发售日期。
- 外部来源链接明确标识并安全打开；失效来源不影响本站正文呈现。
- 路由不存在时显示站内 404，而不是空白或框架错误页。

## 10. 验证标准

实现完成后必须提供以下新鲜证据：

- 依赖安装成功，正式生产构建退出码为 0。
- 类型检查和项目配置的代码检查通过；若构建已包含类型检查，应记录覆盖范围。
- 首页及六个核心内容路由在本地或预览环境返回非错误响应。
- 桌面与移动断点没有水平溢出，导航、主要按钮和内容卡片可用。
- 键盘焦点、移动端菜单、倒计时与减少动态效果按设计工作。
- 各页面 title、description、canonical、Open Graph、结构化数据、sitemap 与 robots 内容匹配对应页面。
- 关键事实逐项对照来源，来源状态标签正确。
- Git 工作区只包含本项目文件，提交不包含密钥或临时构建产物。
- Vercel 生产部署成功，首页与核心路由通过线上请求验证。

## 11. GitHub 与 Vercel 发布

- 在当前工作区初始化独立 Git 仓库。
- 使用清晰的提交记录保存设计、实现和最终验证修正。
- 若本机 GitHub CLI 已登录，创建一个新的公开 GitHub 仓库并推送；仓库名使用简洁的英文 slug。
- 若 GitHub 或 Vercel 未授权，不绕过账户授权，也不把凭据写入代码；请求用户完成一次必要登录后继续。
- Vercel 项目从该 GitHub 仓库导入，使用 Next.js 自动检测配置和生产构建命令。
- 部署成功后记录生产 URL，并对首页与核心路由发起实际请求。

## 12. 明确不在首发范围内的内容

- 用户账户、评论、收藏、云同步或社区功能。
- CMS、数据库、后台管理界面或自动新闻抓取。
- 未公开的完整流程、Boss、收集品、奖杯和最优配装。
- 泄露素材、未经授权的官方 Logo 复刻或对其他攻略站的内容搬运。
- 与攻略和资讯目标无关的复杂动画或三维效果。
